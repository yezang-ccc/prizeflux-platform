# 抽奖算法答辩要点（待学习者自行验收）

本项目把概率精确映射到一百万个整数票号。线性策略每次按奖品 ID 顺序扫描权重，单次 O(n)、构建 O(n)；预计算策略构建一百万项票表，构建/内存 O(1,000,000)，单次选择 O(1)。两者共用票号和排序规则，总概率小于 1 时余票表示未中奖，不做隐式归一化。生产用例目前选线性策略，预计算策略尚未接入运行期配置缓存。

统计实验用固定种子、20 万次抽样侦测实现偏差；卡方量低于阈值并不能证明绝对公平，也不能证明真随机源安全。即使概率分布正确，库存卖完、请求重放、活动关闭和身份冒用也会改变用户看到的结果，因此公平性说明必须同时解释冻结配置、随机源、库存条件更新、幂等及审计边界。

以下问题留给学习者在构建完成后独立回答，不由 Agent 代答或标记通过：为什么不用 double 累加？何时选择线性或预计算策略？未中奖余量如何表示？统计通过为何不能保证业务公平？
